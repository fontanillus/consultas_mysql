NÓMINA 3

16 ejercicios de consultas multitabla e integridad referencial en MySQL.

Descargar nomina3.sql

Ejercicios

Abre un enunciado para ver la explicación, las relaciones y el SQL disponible.

1. Nombre, apellido, sueldo y departamento.

INNER JOIN enlaza cada empleado con su departamento para mostrar su nombre, apellido y sueldo.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.nombre,
    e.apellido,
    e.sueldo,
    d.departamento
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento;
2. Nombre, apellido, fecha de contrato y cargo.

INNER JOIN enlaza cada empleado con su cargo y muestra la fecha de contrato.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
MySQL 
SELECT
    e.nombre,
    e.apellido,
    e.fecha_contrato,
    c.cargo
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo;
3. Mismos datos, ordenados por fecha de contrato ascendente.

ORDER BY ordena las fechas de contrato de la más antigua a la más reciente.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
MySQL 
SELECT
    e.nombre,
    e.apellido,
    e.fecha_contrato,
    c.cargo
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo
ORDER BY e.fecha_contrato ASC;
4. Empleados con sueldo superior a 2000, y departamento.

WHERE selecciona los empleados cuyo sueldo supera 2000. El INNER JOIN aporta el departamento.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.pk_empleado,
    e.nombre,
    e.apellido,
    d.pk_departamento,
    d.departamento
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE e.sueldo > 2000;
5. Empleado más joven y cargo.

El orden descendente deja primero la fecha de nacimiento más reciente. LIMIT 1 devuelve la primera fila.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
MySQL 
SELECT
    e.nombre,
    e.apellido,
    e.fecha_nacimiento,
    c.cargo
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo
ORDER BY e.fecha_nacimiento DESC
LIMIT 1;
6. Empleados que tienen hijos y departamento.

WHERE e.hijos > 0 selecciona a los empleados con al menos un hijo. El INNER JOIN aporta el departamento.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.nombre,
    e.apellido,
    e.hijos,
    d.departamento
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE e.hijos > 0;
7. Todos los datos del empleado de Contabilidad, sin SELECT *.

Se enumeran las columnas de empleado y se filtran las filas por el nombre del departamento.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.pk_empleado,
    e.apellido,
    e.nombre,
    e.sexo,
    e.fecha_nacimiento,
    e.estado_civil,
    e.hijos,
    e.fk_cargo,
    e.fk_departamento,
    e.fecha_contrato,
    e.sueldo
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE d.departamento = 'Contabilidad';
8. Solteros sin hijos, con cargo y departamento.

Dos INNER JOIN aportan el cargo y el departamento. El filtro exige el estado civil Soltero y cero hijos.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.nombre,
    e.apellido,
    c.cargo,
    d.departamento
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE e.estado_civil = 'Soltero'
    AND e.hijos = 0;
9. Compras y Ventas, sin IN.

OR admite cualquiera de los dos identificadores de departamento. El 2 corresponde a Compras y el 6 a Ventas.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.pk_empleado,
    e.nombre,
    e.apellido,
    d.departamento
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE d.pk_departamento = 2
    OR d.pk_departamento = 6;
10. Compras y Ventas, con IN.

IN comprueba si el identificador del departamento está en la lista de Compras y Ventas.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.pk_empleado,
    e.nombre,
    e.apellido,
    d.departamento
FROM empleado AS e
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE d.pk_departamento IN (2, 6);
11. Más de 20 años en la empresa, ordenado por departamento ascendente y antigüedad descendente.

TIMESTAMPDIFF calcula los años completos desde la contratación hasta hoy. Se filtran los valores mayores que 20 y, dentro de cada departamento, se ordenan primero los contratos más antiguos.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.nombre,
    e.apellido,
    c.cargo,
    d.departamento
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE TIMESTAMPDIFF(YEAR, e.fecha_contrato, CURDATE()) > 20
ORDER BY
    d.departamento ASC,
    e.fecha_contrato ASC;
12. Solteros, divorciados o viudos con más de un hijo.

IN selecciona los tres estados civiles y el filtro exige más de un hijo. TIMESTAMPDIFF calcula la edad en años completos.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    e.pk_empleado,
    e.nombre,
    e.apellido,
    TIMESTAMPDIFF(YEAR, e.fecha_nacimiento, CURDATE()) AS edad,
    c.cargo,
    d.departamento
FROM empleado AS e
INNER JOIN cargo AS c
    ON e.fk_cargo = c.pk_cargo
INNER JOIN departamento AS d
    ON e.fk_departamento = d.pk_departamento
WHERE e.estado_civil IN ('Soltero', 'Divorciado', 'Viudo')
    AND e.hijos > 1;
13. Todos los departamentos, incluso sin empleados.

LEFT JOIN conserva todos los departamentos. Si un departamento carece de empleados, las columnas del empleado quedan a NULL.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    d.pk_departamento,
    d.departamento,
    e.nombre,
    e.apellido
FROM departamento AS d
LEFT JOIN empleado AS e
    ON d.pk_departamento = e.fk_departamento;
14. Lista todos cargos registrados que existen en la base de datos, junto con el nombre y apellido del empleado, la edad y estado civil que tiene cada empleado. El listado deberá mostrar también aquellos cargos que no tienen empleados asociados.

LEFT JOIN conserva todos los cargos, incluidos los que carecen de empleados. TIMESTAMPDIFF calcula la edad de cada empleado asociado.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
MySQL 
SELECT
    c.cargo,
    e.nombre,
    e.apellido,
    TIMESTAMPDIFF(YEAR, e.fecha_nacimiento, CURDATE()) AS edad,
    e.estado_civil
FROM cargo AS c
LEFT JOIN empleado AS e
    ON c.pk_cargo = e.fk_cargo;
15. Lista los departamentos sin empleados asociados.

LEFT JOIN conserva todos los departamentos antes del filtro. IS NULL sobre la PK del empleado identifica los departamentos sin empleados.

Tablas y relaciones (FK → PK)

  • empleado.fk_departamento → departamento.pk_departamento
MySQL 
SELECT
    d.pk_departamento,
    d.departamento
FROM departamento AS d
LEFT JOIN empleado AS e
    ON d.pk_departamento = e.fk_departamento
WHERE e.pk_empleado IS NULL;
16. ¿Se puede asignar a un empleado un cargo que no esté registrado en la tabla de cargos? Justifica tu respuesta.

No se puede asignar un cargo inexistente porque fk_cargo es una clave foránea que referencia pk_cargo de la tabla cargo. La restricción FOREIGN KEY garantiza la integridad referencial e impide asignar un cargo que no esté registrado.

Tablas y relaciones (FK → PK)

  • empleado.fk_cargo → cargo.pk_cargo
